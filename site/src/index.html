One deliberate path to deployment

From a diagram to a running version.

Each step answers a different question. The draft is what you are editing. The published version is fixed. A deployment decides which hosts receive it.

  1. 01

    Design & check

    Draw the flow or edit its YAML, TOML, or JSON. Set component options with Vector-aware fields, run sample tests, and check the configuration.

  2. 02

    Publish & choose

    Freeze an immutable version. Preview the target devices or groups, then release all at once, on a schedule, or through a canary.

  3. 03

    Apply & verify

    Each outbound-only agent validates against its host, applies the version, and reports its state. If startup fails, it restores the last working configuration.

Know the boundary

An honest developer preview.

Vectory 0.1.0 works with Vector 0.58.x and can be self-hosted on one Linux server. Agent builds target Linux, macOS on Apple silicon, and Windows x86-64, with different levels of native coverage. Packages and image archives are unsigned; there is no package repository or container registry yet.

Start on a test host, read the security model, and check the detailed compatibility table and known limits before using Vectory for consequential workloads.
