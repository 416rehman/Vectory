Control belongs in the right places

A clearer boundary between what you want and what runs.

Vectory is self-hosted. Your event stream goes from Vector to your destinations; it does not pass through Vectory.

01 / RELEASE

Versions that stay put.

Publish an immutable configuration, compare it with earlier versions, and review who should receive it before deploying.

02 / HOST

Devices keep a say.

Restricted mode and local allowances are set on each host. The server cannot widen them; supported credential fields can use host-held secrets.

03 / EVIDENCE

Status with a reason.

See the version a device reports running, the stages it passed, and the issue that stopped it. File delivery alone is never called activation.

01 / FASTEST START

Start with the bundle.

On Linux x86-64 with Docker and Compose v2 running, use the prebuilt preview kit. No Rust, Go, or Node toolchain is needed.

  1. 01
    Download the preview kitGet the unsigned kit and verify its SHA-256 from the release page.
  2. 02
    Extract and startFrom the extracted kit directory, run the local start script.
  3. 03
    Open 127.0.0.1:8080Create the first administrator, then connect a test device.
Run in a Linux terminal with Docker ready
curl -fL --proto '=https' https://github.com/416rehman/Vectory/releases/download/v0.1.0/vectory-0.1.0-preview-linux-amd64.tar.gz -o vectory-0.1.0-preview-linux-amd64.tar.gz && curl -fsSL --proto '=https' https://github.com/416rehman/Vectory/releases/download/v0.1.0/SHA256SUMS -o release-SHA256SUMS && grep -E '^[0-9a-f]{64} vectory-0[.]1[.]0-preview-linux-amd64[.]tar[.]gz$' release-SHA256SUMS | sha256sum --check --strict - && tar -xzf vectory-0.1.0-preview-linux-amd64.tar.gz && cd vectory-0.1.0-preview-linux-amd64 && ./start.sh

02 / OWN SERVER

Run it on your host.

Run the prebuilt images with Docker Compose on one Linux server. Bring your DNS name and TLS certificate, then choose who receives each version.

Read the install guide ↗ Start on a staging host before consequential workloads.
