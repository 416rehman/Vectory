# Independent implementation review

Reviewed by the security/release workstream while the backend and agent workstreams implemented the product. This is source review plus executed regression evidence, not a third-party audit or production certification.

Executed independent adversarial network suite: `tests/security/protocol_test.go`, 21 passing subtests on a newly launched native Rust server with ephemeral CA and SQLite state. It verifies authorization, CSRF, TLS trust and protocol version, CSR proof/identity, token scope/use/revocation, transactional uniqueness, idempotency key binding, manifest signature/binding, artifact isolation, identity spoof resistance, and revocation with an asserted reused TLS connection. Additional checks cover TOTP replay, one-use recovery codes, password-gated MFA disable, other-session revocation, and an administrator-authorized exact-name device replacement that receives a fresh unmanaged UUID and cannot reuse its old certificate. The test does not reuse or mutate the ordinary product fleet.

The agent's actual negative tests were independently reviewed and rerun for stale configuration/policy generations, same-generation content substitution, signature/recipient/nonce mismatch, artifact traversal/size, explicit rollback with a newer generation, exec/secret providers, implicit file/network/listener resources, environment substitution, dynamic resource templates, external VRL capabilities and console startup-log forgery. Passing these cases does not establish a complete parser or OS sandbox.

The runtime API never trusts proxy certificate headers; agent identity comes from the actual TLS peer certificate fingerprint and active DB registration on each authenticated request. Configuration is structurally validated server-side and never executed with server credentials. Exact activation is only reported by the explicitly adopted child process path after staged validation, startup evidence and bounded liveness; unrelated `/health` responses are not accepted as activation proof.

Device-local secrets were reviewed across typed resolution, pinned reads, effective-policy validation, monotonic pre-attempt revision persistence and crash recovery. Reference templates remain immutable; effective hashes can differ only for explicitly secret-bearing versions with matching template proof and revision evidence. Generic diagnostics suppress subprocess output. Narrow supported credential fields are implemented; arbitrary secret providers remain intentionally unsupported.

Residual gates: full operational credential/signing-key rotation/recovery drills, executed container isolation for hostile validation, native OS service/ACL/reboot/upgrade coverage, power-loss on physical filesystems, signing/publication identities, resource/DoS capacity and long outage experiments. Agent-supervised Vector intentionally shares the agent supervisor lifecycle; loss/stop of that supervisor requires the configured OS service to restart it. This limitation must remain visible. Review the product specification and acceptance report before deciding release readiness.
