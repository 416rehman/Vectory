# Requirements-to-tests checklist

The [product specification](../product-specification.md) asks for a checklist that maps each requirement to the tests behind it and says what was run, observed and still unverified (section 2, line 54; section 16, line 336). This is that checklist. One row covers one testable sentence or one behaviour spread over a few sentences. The rows start from the specification audit of commit `7655be4` and were re-checked against commit `a469266` on 2026-09-29; rows about notifications, device secrets and CI were derived again.

Specification: `docs/product-specification.md`, 342 lines, SHA-256 `4b47c55636559a8dadd3877b4f094189c42c3d05afadb0bdb734b962f31264d8`. The checker fails when the specification changes, so that every line reference is re-checked.

**Status.** **Met**: implemented, and a test, CI step or document named in the row proves it. **Partial**: part of the requirement is met; the gap says what is not. **Missing**: nothing implements it. **Unverified**: implemented, but nothing executed proves it yet.

**Evidence.** Each backticked item is checked by `node scripts/check-requirements.mjs`, which runs in CI: a path must exist, `path::Name` must also contain `Name` (a test function, a subtest or a symbol), and `ci:job/text` must name a job of `.github/workflows/ci.yml` with a step whose name or command contains `text`. The kind of evidence follows in brackets: unit (in-process, mocks allowed), native (real Vector or a real OS feature), HTTP (a real server process), browser (the real dashboard; synthetic API responses unless stated), build, doc, manual (run by hand, not in CI). Compilation, a mock test and a native test are different evidence.

**Totals:** 61 Met, 49 Partial, 1 Missing, 6 Unverified.
