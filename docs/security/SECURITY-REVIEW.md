Executed independent adversarial network suite: `tests/security/protocol_test.go`, 21 passing subtests on a newly launched native Rust server with ephemeral CA and SQLite state. It verifies authorization, CSRF, TLS trust and protocol version, CSR proof/identity, token scope/use/revocation, transactional uniqueness, idempotency key binding, manifest signature/binding, artifact isolation, identity spoof resistance, and revocation with an asserted reused TLS connection. Additional checks cover TOTP replay, one-use recovery codes, password-gated MFA disable, other-session revocation, and an administrator-authorized exact-name device replacement that receives a fresh unmanaged UUID and cannot reuse its old certificate. The test does not reuse or mutate the ordinary product fleet.

The agent's actual negative tests were independently reviewed and rerun for stale configuration/policy generations, same-generation content substitution, signature/recipient/nonce mismatch, artifact traversal/size, explicit rollback with a newer generation, restricted-mode denial of exec/secret providers, implicit file/network/listener resources, environment substitution, dynamic resource templates, external VRL capabilities and console startup-log forgery. Passing these cases does not establish a complete parser or OS sandbox.

The runtime API never trusts proxy certificate headers; agent identity comes from the actual TLS peer certificate fingerprint and active DB registration on each authenticated request. Configuration is structurally validated server-side and never executed with server credentials. Exact activation is only reported by the explicitly adopted child process path after staged validation, startup evidence and bounded liveness; unrelated `/health` responses are not accepted as activation proof.

Device-local secrets were reviewed across typed resolution, pinned reads, effective-policy validation, monotonic pre-attempt revision persistence and crash recovery. Reference templates remain immutable; effective hashes can differ only for explicitly secret-bearing versions with matching template proof and revision evidence. Generic diagnostics suppress subprocess output. Narrow supported credential fields are implemented; native secret providers are additionally supported when the host operator explicitly grants full Vector mode. Those providers resolve on the device and inherit Vector's OS permissions.

Residual gates: full operational credential/signing-key rotation/recovery drills, executed container isolation for hostile validation, native OS service/ACL/reboot/upgrade coverage, power-loss on physical filesystems, signing/publication identities, resource/DoS capacity and long outage experiments. Agent-supervised Vector intentionally shares the agent supervisor lifecycle; loss/stop of that supervisor requires the configured OS service to restart it. This limitation must remain visible. Review the product specification and the [requirements checklist](../internal/REQUIREMENTS.md) before deciding release readiness.

## Staged MFA sign-in

Correct credentials for an MFA-enabled account return only a five-minute challenge; no user profile, session cookie or CSRF token is issued. Incorrect credentials have the same response for unknown accounts and accounts with or without MFA. The server retains only a hash of the random challenge, permits one pending challenge per account, and applies a durable five-attempt budget plus account/global rate limits. The factor endpoint checks current enabled state, account revision, password identity and MFA enrollment under the writer transaction. Account/enrollment changes, explicit logout, other-session revocation and startup invalidate pending challenges.

Independent review found that the retained combined credentials-plus-factor endpoint could commit a recovery-code deletion after its audit write failed. The backend now rolls back infrastructure failures on both login paths. Injected failures at recovery audit, successful-login audit and session insertion verify that recovery code, challenge, audit and session state roll back together. Concurrent completion consumes a challenge once; a new challenge cannot reuse a recovery code or accepted TOTP step.

The current account review (`docs/evidence/account-review.json`) passed 19 real-HTTP groups on disposable instances using server `01a54e8e2907d998dcd55a62f868a0b6fce18a0f242596cfbad91bd44086a3f1`. It also passed 116 generated-schema validations over session/challenge responses. The earlier ten-group account result (`docs/evidence/account-review-before-staged-mfa.json`) remains historical. Expiry and failure injection use isolated databases; no preview accounts or ordinary fleet state were modified. These tests do not establish phishing resistance or an authenticator-recovery bypass.

## Audit browsing and prepared exports

Audit history and details use allowlisted projections, strict filters and authenticated reads for every workspace role. Exact device filters use persisted UUID relationships, including explicitly recognized compound events; they do not infer current group membership or combine replacement identities by name. Arbitrary stored extensions, configuration bodies and credentials are excluded. Exported names describe the snapshot's current labels, not historical names.

An explicit CSRF-protected request prepares a complete JSONL file from one SQLite snapshot. Metadata records the normalized filter, sequence cutoff, count and limits; the completion line hashes the exact event lines. The ready response hashes the whole file. Downloads require the original user and session, recheck live authorization between bounded chunks, and declare the full Content-Length so a revoked or interrupted transfer cannot pass as a complete shortened file. Already buffered bytes cannot be retracted. These hashes are integrity checks, not signatures or tamper-proof audit attestation.

Two preparations and four downloads may run concurrently. Four file reservations in total, at most two per account, bound managed exports to 512 MiB at the 128 MiB per-file cap. Reservations include preparation, active downloads after discard, and files awaiting failed OS deletion; cleanup retries retain capacity until removal succeeds. Files use private OS permissions, expire after ten minutes and are removed on startup. Preparation and downloads use 120-second cooperative deadlines; stalled operating-system file I/O cannot be forcibly preempted. Long snapshot reads can temporarily retain SQLite WAL pages.

The independent HTTP review (`docs/evidence/audit-review.json`) covers snapshot writes and renamed actors, exact hashes/counts, original-session isolation, Windows DACLs, locked-file cleanup, quota rejection, actual stream revocation and restart cleanup. The pre-fix query-plan observation (`docs/evidence/audit-query-plan-before.json`) and locked-file quota failure (`docs/evidence/audit-cleanup-before.json`) remain historical evidence. These are bounded synthetic tests, not sustained capacity or disk-exhaustion qualification. Legacy full collections remain available for compatibility; substring/count scans and deep offset pagination still cost database work.

## Explicit full Vector mode review

The local `--allow-full-vector-config` grant is a deliberate trust expansion for authorized publishers. It enables every native component and global setting accepted by the installed Vector build, including native exec, provider, environment, enrichment and secret capabilities. Existing device policies remain restricted. The server accepts only the enumerated device-reported mode on enrollment and authenticated heartbeat; missing legacy fields mean restricted, invalid fields fail, and remote policy rejects any mode field. The dashboard checks the reported mode before sending configurations that require it. It cannot enable full mode.

Full mode shares the Vector and agent OS principal. A trusted publisher with native exec is therefore also trusted with that principal's accessible files and process capabilities. Startup logs and file digests provide operational activation evidence, not attestation against that publisher; console-output separation only protects the restricted profile. Native secrets and interpolation suppress diagnostics, but freeform strings and programs cannot be proven secret-free by a field-name heuristic. Sensitive credential fields must use references, and operators must not place credentials in arbitrary freeform configuration.

New independent regressions cover authenticated mode reporting, legacy fallback, invalid modes, rejected remote widening, provider-only immutable publication, literal topology cycles, wildcard/native-port deferral, preserved full configuration bytes, plaintext credential rejection, and deployment review gates for restricted versus full devices. The pinned native worker executes passing and deliberately failing pipeline unit tests and discards raw diagnostics; provider/secret/environment bundles return explicit deferred results without executing or resolving their resources. Container isolation is still unexecuted evidence, not implied by these native worker tests.

## Second independent review, after the overhaul

A reviewer who had not written or reviewed the code re-tested every earlier finding against the running build and then attacked the validator sandbox, the agent's local policy and signed manifests, the API authorization matrix (99 routes across five roles), device identity, the install endpoints and the supply chain. It found no remote code execution, request forgery, authorization bypass, injection or off-host secret leak. This is an internal review, not a third-party audit.
