# Threat model and risk decisions

Scope: single-instance self-hosted control plane, browser administrators, reusable enrollment tokens, outbound agents, locally managed Vector. This is an implementation checklist; passing evidence belongs in the [requirements checklist](../internal/REQUIREMENTS.md) and the CI workflow `checks`, not in this document.

Assets include control-plane signing/device-CA and MFA sealing keys, sessions, enrollment verifiers, agent identity keys, immutable reference templates, device-local secret files, rendered managed/recovery configurations, generation/revision counters, and group membership. Pipeline event payloads are not telemetry.

| Boundary / attacker                               | Required control                                                                                                                          | Failure behavior / acceptance probe                                                                                                              |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Network attacker at bootstrap                     | HTTPS verified before sending token, independently provisioned server CA, TLS 1.3                                                         | Wrong CA/hostname fails without token disclosure; no automatic CA fetch/trust                                                                    |
| Reusable token thief                              | Random verifier-only tokens; expiry, revoke, usage/prefix limits, optional preapproved names (each once); unmanaged enrollment            | Valid token cannot select groups/production access; token labels are descriptive only; duplicate-name transaction admits one identity           |
| Unauthenticated browser                           | Locally supplied one-time bootstrap secret; password hash; generic auth errors; rate/size bounds                                          | No fleet/name enumeration or public default administrator                                                                                        |
| Stolen password or replayed pre-session MFA token | Password-first challenge with no session authority; five-minute expiry, five attempts, account rate limits and live credential/MFA checks | No MFA disclosure for bad credentials; account changes, enrollment changes, logout, session revocation and restart invalidate pending challenges |
| Cross-site request / stolen cookie                | HttpOnly Secure SameSite=Strict session, CSRF token, role check on every mutation                                                         | Missing/mismatched CSRF and viewer mutation fail                                                                                                 |
| Enrolled hostile device                           | Dedicated CA plus active certificate registration on every request                                                                        | Spoofed certificate headers have no effect; revoked pooled connection cannot heartbeat/download                                                  |
| Device-CA key theft                               | Registered fingerprint required on every request; offline `rotate-device-ca` with one bounded previous CA; `retire-device-ca` after renewal | A certificate minted with the CA key but never issued is refused (401); after retirement a certificate from the old CA fails the TLS handshake  |
| Manifest or artifact replay                       | Ed25519 exact bytes, device UUID, fresh request nonce, expiry, persisted generation/digest binding                                        | Wrong recipient, reordered/same-generation changed content, bad digest/signature fail                                                            |
| Malicious pipeline author on a restricted device  | Configuration treated as code; bounded local capability allowlist; no shell; immutable sole managed path                                  | Exec, native providers and arbitrary roots/endpoints denied before validation/apply                                                              |
| Authorized publisher on a full-mode device        | Host operator explicitly grants `full_vector_config`; signed delivery and native validation/tests remain mandatory                        | Publisher is trusted with Vector's environment, native exec/providers, files and network under its OS principal; this is not an OS sandbox       |
| Compromised local low-privilege process           | Restrictive state ACL/permissions, path/reparse checks, fixed executable/service                                                          | Symlink/path escape rejected; identity inaccessible to unrelated users                                                                           |
| Local credential file substitution                | Typed field references only, operator bindings, pinned no-follow handles, owner/ACL/single-link checks, effective-policy revalidation     | Symlink/hardlink/broad ACL rejected; secret values excluded from diagnostics, heartbeat and template exports                                     |
| Crash / disk exhaustion                           | Journal, staged validation, flush + atomic replacement, retained last-known-good                                                          | Each boundary recovers a whole file; uncertain activation never becomes verified                                                                 |
| Hostile telemetry / large fleet                   | Bounded request, metrics, queues, retention; sanitized diagnostics                                                                        | Resource bounds and drop counters; no config/secrets in diagnostics                                                                              |
| Backup theft / old restore                        | Backup contains required keys and consistent SQLite snapshot; restricted encrypted storage                                                | Restore preserves trust but cannot lower agent generation floors                                                                                 |
| Supply-chain attacker                             | Lockfiles, checksum catalog, SBOM, provenance and real signing gates                                                                      | Missing artifact omitted; unsigned development outputs explicitly labeled                                                                        |

Consequential decisions:

1. Browser TLS terminates at a private reverse proxy. The HTTP API must not be host-exposed. Agent TLS terminates in Rust; no forwarded-header authentication is trusted. Enrollment is the only agent operation without a device certificate.
2. The server does not execute untrusted Vector configuration with production credentials. Structural checks may be available while real isolated validation is unavailable; results must preserve this distinction.
3. A compromised authorized operator can change pipelines within device-local policy. Enrollment does not establish hardware identity. Approving devices and privileged group membership remains a deployment-capable operation.
4. A compromised machine administrator can access its local keys and configuration; remote protocol checks cannot protect against that administrator. Restricted agent control does not offer arbitrary command execution. Full Vector mode deliberately grants native exec and provider capabilities to authorized publishers under the adopted process's permissions; the dashboard cannot grant or widen that local permission.
5. Exact activation requires evidence for the specific applied configuration. File write, reload request, and a generic healthy old process are insufficient. Unknown verification remains visible and blocks canary success.
6. This version's release cannot claim OS, restart, MSI, signed repository, capacity, or isolated validation gates without measured evidence. Missing credentials and machines are recorded individually.
7. Vectory-managed `vectory-secret:NAME` references are restricted to the credential fields of a generated table: every field of the pinned Vector schema typed `SensitiveString`, plus reviewed plain-string credentials, per section and component type. The agent and the server each compile their own copy, drift-tested against the schema in CI. The agent substitutes only at its own table's paths, never at paths the server names, so a compromised server cannot route a host secret into a URL, header, path, command or VRL program. It can still point a credential-bearing component at another destination: restricted devices bound that with their local network allowances; full-mode devices do not. Agents report bound secret names (never paths or values). Full mode also permits native Vector secret providers and environment references resolved only on the device. Rendered files necessarily hold plaintext for Vector and share its current OS principal; stronger isolation from a compromised Vector child remains a gate. Template/effective hashes identify revisions and do not conceal weak secrets against guessing.

Review actual implementation against every row. Outstanding defects must remain visible; this document is not security certification.

8. Enrollment and authenticated heartbeats report `configuration_mode`; absent legacy reports mean restricted. This is reported configuration, not hardware attestation, and an already compromised device can lie about it. The deployment review checks reported mode while the local agent remains the authority for enforcing its own policy.
9. Full mode does not protect supervisor credentials or startup log evidence from an intentionally malicious publisher with native exec under the same OS principal. Fixed executable ownership, managed-file digest, process startup record and bounded liveness remain operational evidence, not independent attestation against that publisher. Separate principals and a protected supervisor channel would be required for that stronger boundary.
10. Isolated validation and pipeline tests use pinned Vector with a scrubbed environment, input/output/deadline/concurrency limits, and no production mounts or secrets. Provider, native secret, environment and external-file configurations explicitly defer to the device instead of resolving those resources on the API host or worker. Executed container isolation remains a separate release gate.
11. All authenticated workspace roles can read and explicitly export audit metadata. Prepared exports are private, temporary, bound to their originating user/session and subject to live authorization during download. Resource reservations survive active transfers and failed OS deletion. Export hashes establish file integrity, not a signature or independent proof against a compromised server administrator. Auth revocation cannot retract bytes already buffered by a transfer.
12. A password-verified MFA challenge is a separate, hash-only capability for the factor endpoint. It creates no browser session or CSRF token and cannot authorize other API calls. Successful factor verification, recovery-code consumption, challenge deletion, audit and session creation commit in one transaction. Existing clients may submit credentials and a factor together; that compatibility path must preserve the same atomicity. Restart clears all pending challenges, including those restored from backup.
