# Vectory interaction and visual design

The pipeline graph is the primary editing workspace. It fills the available page, with a selected component's settings in a right-hand panel. Never move the graph into a full-screen modal or replace it with a guided form. Code is the alternate view of the same configuration; there is no separate Steps view.

Request recovery must not disappear when local storage is damaged. Deployment reminders appear in one account-scoped review list, including unreadable records. A readable request can retry its frozen contents; an unreadable one supports only an exact-ID server lookup or history. New deployment and rollback sends wait for this review. A confirmed result remains visible if local cleanup fails, and explicit dismissal preserves a peer's repaired reminder. Keep the status and available action clear without exposing the damaged payload.

Page failures stay inside the main content area so navigation and account controls remain usable. Distinguish failed or stalled page-file loads from an unexpected rendering fault. Bound lazy imports at 30 seconds; consume obsolete results without replaying or automatically reloading. The recovery view uses a focused heading, concise next step, deliberate Reload page action and direct static-help link. Reload consults surviving navigation guards, but a crashed page's unsaved component state may already be lost and must never be described as preserved. Healthy pages do not remount for query-only navigation. A missing initial entry bundle is outside this boundary because the app cannot start.

## Aesthetic direction

We inspected Base44's rendered page, loaded CSS, font declarations and client scripts on 2026-09-26. Its hierarchy comes from tightly tracked display type, warm neutral surfaces, decisive dark text, restrained borders and short, purposeful transitions. The reference uses Dazzed display type and Geist UI text. Vectory applies those principles to a working configuration tool; its layout follows pipeline tasks rather than Base44's marketing cards. No Base44 font files, source code or branding are bundled.

Vectory uses self-hosted Instrument Sans, including variable weights, under the SIL Open Font License. The wordmark and V symbol are local SVG. Warm paper (`#f5f3ef`), white surfaces, dark ink (`#252429`), charcoal actions (`#302e2e`) and cobalt selection (`#4055dc`) form the light palette. Dark mode uses warm charcoal surfaces and a lighter blue focus accent. Color has a job: selection, action or actual state. Orange is not the brand color.

Use the shared scale, compact six-pixel control corners, hairline separators and clear text hierarchy. Avoid decorative status dots, excessive pills, marketing copy, uppercase micro-labels and repeated explanations. Make actual values and useful actions easy to see. Motion is short and honors reduced-motion preferences.

Schema fields share one ordered list across curated and native settings. Each field has a clear boundary and a header containing its label, required marker, a tiny help control and one actions menu. Help appears on hover, focus or tap; null, JSON and removal actions stay inside the field menu. Optional fields are selected from a compact searchable floating dropdown, then join the same list; meaningful field icons are used where known without generic icons on every result. JSON values share a highlighted editor with local diagnostics, formatting and explicit apply/discard actions. Text links to documentation carry an outward-link indicator; circle-help icon actions do not.

## Information architecture

The main navigation has four destinations: Overview, Pipelines, Devices and Activity. Groups and agent settings belong inside Devices. Deployments, schedules, issues and audit history belong inside Activity. The user button at the bottom opens an anchored account dropdown with Settings and Vectory documentation. People & security is a tab inside Settings. These destinations do not repeat as separate sidebar entries. Appearance uses a labeled Light / Dark / Auto icon switch; Auto follows the system while explicit choices remain stable. Sign out is separated and styled as a danger action. In the pipeline workspace the desktop sidebar contracts to a labeled, keyboard-accessible icon rail to leave room for the graph.

The overview answers what needs attention and what changed, using actual API state. Numbers, attention items and recent activity have a flat, readable hierarchy. Device details occupy a focused page. Technical digests, identifiers and recovery controls use progressive disclosure.

A device page remains tied to its requested identity. Reject a different device, telemetry envelope, version or pipeline before consuming its fields; a mismatched response clears the affected resource and dependent actions until a matching refresh. Keep the route and selection intact, show an actionable error and provide a way back. Selected-device banners use the same bounded, cancellable resource loading and offer Try again or Clear selection. Ordinary transient read errors may retain previously verified data with an error, while identity mismatches never turn into empty-state setup advice. Independent reads do not imply an atomic assignment snapshot.

Find a page is a keyboard-accessible combobox with one active result. Page names, task aliases and concise descriptions support discovery; icons match the destinations. Arrow keys move the active result without leaving the search input, Enter navigates, and Escape returns focus. Reopening starts a fresh search. The current page is marked, enrollment follows role access, and documentation explicitly opens in another tab. Existing pending-edit guards apply to search navigation.

Tabs and view switches pair visible text with a consistent 16-pixel outline icon through the shared `TabLabel`. Icons inherit the selected or muted text color and remain hidden from assistive technology; labels, keyboard navigation and selected states retain their existing meaning. Narrow layouts preserve labels and allow navigation to scroll within its own row.

Record tables use the shared `DataTable` with sorting on column titles and filter popovers beside the relevant title. Search, refresh and page actions stay in the toolbar. Active filters and sort directions remain visible in the headers, including empty and loading results. Server-paged collections sort and filter the full query before pagination; local collections do the same before slicing. Narrow screens scroll the table horizontally and keep headers available. Filtering a deployment or recovery review changes only its display, never the reviewed target set. Code diffs use the shared rendering shell with fixed line order and no record-sorting controls.

Shared resource reads have a 30-second response deadline, including the response body. Background polls never supersede a read already in flight. An explicit refresh replaces it; navigation and unmount cancel abandoned work. Late responses cannot replace newer data, and a failed refresh retains the last loaded resource with an error. A timeout describes a failed read, not a change to the underlying device or deployment.

Startup uses one bounded status/session read with Retry connection and a public documentation link. Only an authoritative absent-session response opens guest sign-in; unavailable or unreadable session checks retain a recoverable connection error. Sign-in, setup, verification and public password reset synchronously claim their own request and stop waiting after 30 seconds, including body reads. Unknown results clear submitted secrets and replace the form with explicit recovery. Check sign-in/setup status performs reads only; a positive session must be enabled and match the intended email. Negative snapshots do not prove the original request failed. Starting a new sign-in or setup is a separate deliberate action after a completed check. Unknown password reset instead directs the person to sign in using the intended new password. Passive account refresh remains in place, bounded and cancellable, preserving unfinished editor work.

Sign-out uses one retained dialog controller per displayed account. Its bounded request requires initial draft consent and an explicit `ok: true` receipt; duplicate submissions are claimed synchronously. Stop waiting, close and Escape immediately retire local ownership while preserving the unresolved review in the account menu. Recovery reads the current session without restoring authority or adopting credentials. A retry requires the original user and exact original CSRF, plus unchanged local authority, and sends that frozen CSRF explicitly. A newer sign-in requires a fresh guarded workspace reload. An absent-session snapshot disables protected requests but keeps local work mounted; Go to sign in checks the current draft guard. A later known credential change invalidates that exit snapshot. Only an owned direct success in the still-open original modal uses the initial leave consent. Focus returns to a visible opener or shell/sign-in fallback, and narrow dialog actions wrap without overflow. Closing is never described as server rollback or cookie cancellation.

Password changes and other-session revocation own a separate bounded request for the displayed account and exact session. Closing is always available and retires ownership synchronously. Clear every submitted password immediately and never persist it for replay. Require an enabled same-account, rotated session receipt before adopting a password-change result; require `ok: true` for revocation. A current-session read cannot prove either operation completed, so do not offer a misleading status check. An uncertain password change directs the person to sign in with the intended new password. An uncertain revocation offers a separate scope review and fresh password entry, explicitly including sessions created since the earlier attempt. Keep independent unresolved summaries when either dialog closes or the other action opens; these live only for the current People & security page. Changed sign-in context requires an explicit fresh reload. Sign-in departure and reload recheck the current navigation guard, preserve focus on veto, and never let stale callbacks rotate credentials or replace newer account state.

Enrollment uses the same descriptive radio dropdown as workspace roles. Configuration mode starts unselected; each option explains its capabilities and host-owned permissions inside the menu, with a short selected summary in the control. Certificate trust offers the device's system trust or a public certificate file. Private trust reveals the device-local path and concise self-admin acquisition guidance, including the development CA example and a complete help page. It never infers trust from browser access, fetches an unverified certificate or treats a typed path as a successful connection. Both menus close and disable while token creation is pending.

## Pipeline editing

The component sidebar is a softly framed panel with a compact icon, component name and ID header. Its fixed Configuration toolbar contains Add field; related existing properties sit in titled cards with small category-colored icons. Sections such as Sampling, Encoding, Connection and Delivery appear only when applicable fields are present. All fields stay mounted in one schema editor so conditional validation and unfinished values retain their scope. Nested properties keep their full available width. Close with the header X or Escape, with unfinished-edit guards and focus returned to the node. Save state lives in the main toolbar; the sidebar has no Done button or duplicate save footer.

Closing component properties preserves the current canvas viewport and cancels unfinished opening motion. It never schedules a delayed Fit graph that can move a button between pointerdown and click. Explicit Fit graph, initial framing and adding/removing components retain their existing behavior.

Sources flow from left to right through transforms to aligned destinations. Node titles and connection handles remain legible; named outputs have separate rows. A source or transform whose branch has no path to a destination uses a dashed border, a quiet surface and a compact No destination hint. Controls and text retain full opacity; errors and selection remain distinct. The hint updates with connections and Undo, never changes configuration or blocks validation, and stays conservative around native dynamic inputs. Arrange graph reduces crossings, while explicit drop and drag positions remain under the user's control. Panning, zoom, fit and a minimap for larger pipelines support navigation. Clicking a node opens the right panel without covering the whole graph. On narrow screens the panel occupies the canvas region while the page header remains available.

One toolbar above the canvas contains a shared Graph / Code switch on the left, with validation, settings, Actions and publication grouped together on the right. Check results are anchored to their button and share transient hover behavior with field help: moving away from both trigger and popup dismisses it, even after a mouse click. Keyboard focus retains access, Arrow Down enters the popup, and Escape dismisses it; touch users tap to open and tap outside to dismiss. Hovering cached validation results never runs another check. The page header contains pipeline identity and description; both open Pipeline details with keyboard and pointer access. Save state is a compact indicator beside the save and publish controls, with full draft/version context on hover and for assistive technology. Pending edits and failed saves remain explicit. Undo, redo, zoom, animated fit and arrangement are floating canvas controls. Right-clicking empty canvas opens the searchable component menu; dragging an output onto empty canvas opens compatible choices and connects the selected component to that exact output without rewiring existing branches. Add component is a separate, labeled floating button at the canvas's upper left, with a blocks icon distinct from zoom. It uses the same compact neutral surface, hairline border and six-pixel corners as the surrounding controls. It provides the same search for keyboard and touch users and steps aside while a connection is being dragged so candidate guidance stays clear.

The searchable picker exposes the full versioned component inventory. Nodes show recognizable local service icons and useful configuration summaries without invented telemetry. The properties panel edits settings; connections belong on the graph and dynamic input patterns remain available in Code view. Its Configuration toolbar keeps Add field above the scrolling property list. Nested properties are directly visible in full-width sections with small property paths; nesting never adds repeated horizontal gutters. Matching required constants remain serialized without redundant inputs, while optional fixed fields keep their removal actions. Schema conditions and dependencies update requiredness and available fields, with reasons in the compact info control. Unfinished dependent edits cannot be silently unmounted, and inactive stored values remain preserved. Unknown conditions stay conservative rather than inferring behavior from prose. Generic Fields accordions and whole-component JSON do not appear in the inspector. Names identify components; renaming rewires literal input and native test references. Imported unknown fields, wildcard expressions and opaque values remain preserved.

Blue sources, purple transformations and teal destinations share category colors across nodes, picker results and properties headers, always accompanied by text. Canvas nodes follow the supplied card reference: soft rounded corners, thin category borders, restrained shadows, tinted icon tiles, an inset header divider and a monospace ID pill. Small uppercase category labels distinguish roles above the stronger component title. The canvas retains its visible dot grid. Popup menus close on outside interaction and Escape; keyboard focus remains visible without an oversized search-input ring.

Category-tinted node headers make event roles visible at a glance. The Connection style control offers curved, square right-angle and straight lines with visual samples. Its preference stays on the browser and applies to existing edges and drag previews without changing pipeline data. All styles retain broad invisible selection targets. Selecting a line exposes both endpoint grips and its action menu; compatible ports highlight during connection creation and reconnection. Existing endpoints dropped on blank canvas disconnect, invalid drops preserve the original, and Escape cancels. Reconnection updates the exact stored input atomically and preserves other branches and patterns. Node and edge menus have keyboard equivalents, and the canvas shortcut help explains movement, deletion, duplication and undo. An always-visible ellipsis in the node header opens the shared properties, duplicate, disconnect and remove menu; read-only nodes offer properties alone. Escape returns focus to the opener. Node geometry and automatic layout share dimensions, including named-output rows and primary handles aligned to the header divider. Explicit reconnections retain node positions.

Hovering a connection highlights that exact edge and its two endpoint cards. Unrelated lines fade, while unrelated cards lose their shadow and category emphasis without reducing text or control contrast. Keyboard edge focus uses the same transient treatment. Pointer clicks do not pin it; leaving, Escape, connection gestures, menus and view changes clear it. Parallel named-output edges remain distinct, hit targets stay intact, and reduced-motion and increased-contrast preferences are respected. Highlight state never enters configuration, saved graph layout or validation state.

Configuration controls derive from the pinned schema. Strings can represent URLs, paths, templates, code, secrets or ordinary text. Lists have ordered rows. Maps have editable keys and typed values. Nested objects reveal their actual fields. Discriminated branches and string/object alternatives expose explicit choices. Optional absence, null, defaults and empty values stay distinct. Validation explains the affected field. Unapplied invalid drafts remain local and must be resolved or deliberately discarded before leaving. JSON remains an escape hatch.

Code view uses locally bundled syntax highlighting, line numbers, folding and diagnostics for YAML, JSON and TOML, with explicit format, copy and apply controls. Dropped files share the same parser. A valid import fills an empty draft directly; replacing existing configuration requires a reviewable diff in the selected source format. Pending field edits and stale file reads never silently overwrite the draft. Local diagnostics remain distinct from native runtime validation.

Save status uses a small icon and short text label, without a badge or extra header row. Drafts save explicitly with optimistic concurrency; Discard changes returns to the last acknowledged revision. Publishing saves pending edits before creating an immutable version and reviews that exact revision before choosing devices. Runtime validation and device-only validation are distinguished honestly. Enrichment tables, secret providers, global options and native tests are part of the same pipeline.

Deployment review separates the requested change from its priority outcome. It uses resource-specific server candidates, links to a higher-priority assignment and keeps priorities under deliberate operator control. Eligibility never implies release or activation. Creation keeps a compact receipt open with the exact deployment or schedule link and a Close action; navigation retains unfinished-edit guards. A successful HTTP response without matching request identity keeps the recovery reminder and offers a status check or history; it cannot appear as a confirmed receipt or enable a new send.

Assignment removal reviews each device's current and projected desired state. Friendly pipeline/version and assignment names lead; policy values remain explicit. A fallback, unmanaged local configuration, default policy and unreleased candidate have distinct explanations. Excluded historical identities remain visible. Filters never change the confirmed scope. The server binds the actor and actual removal effects to the review; changed membership or fallback requires a fresh review and a separate confirmation. An uncertain response offers an exact-assignment status check, never an automatic resend. Confirmation stays visible when the underlying deployment summary refreshes. Removal does not imply stopping Vector or verified activation.

## Documentation and verification

Enrollment token recovery keeps the operator in context. A quiet request card offers an exact status check, while one dialog explains whether a token was created, remains unknown or was cancelled. Cancellation closes the request against late arrivals and revokes its token, without disconnecting existing devices. A missing response never returns to an unguarded Create action. The secret stays in memory only: closing its dialog offers Show token on the same page; explicit acknowledgment clears it. A reload or session change leaves a nonsecret reminder, and no history view can reveal the old secret. Unknown revocation offers Check current status before another deliberate confirmation. Controls recover after each bounded wait.

Pipeline creation and duplication retain the exact reviewed request before sending. An uncertain response keeps a quiet account-specific reminder; a single recovery dialog shows its status before original details and keeps actions visible on narrow screens. The library and editor's Actions menu expose recent pipeline requests. Recovery opens the current original result without replacing the editor's draft or bypassing its unfinished-edit guard. Source edits after duplication cannot change the recovered copy, and retries never adopt a newer source revision. Only new create/duplicate submissions wait for unresolved requests; editing and archival remain independent.

Rollback uses the same recovery reminder as deployment creation, with an operation type and original rollout identity bound to its request key. Its receipt links directly to the replacement deployment. Receipts and status lookups must echo the exact request, operation and rollback source before the dashboard accepts them or clears a reminder. The receipt contains the original result's current state; changing status or membership is not an identity mismatch. A compatible exact-request lookup is required before retry, and new sends require advertised request-correlation support. Creation and recovery calls stop waiting after 30 seconds without claiming that the server cancelled them; late responses cannot replace the recovery state. Device retry sends the reviewed desired version and generation and requires advertised server support for transactional preconditions. Stale, paused or ambiguous outcomes trigger a status check, never an automatic retry of newly displayed scope. The last verified generation must not be presented as the failed-attempt generation.

Application feedback binds a candidate attempt to its desired generation, version, template and local-secret revision. Device explanations use safe failure categories for that exact candidate; unrelated or older errors cannot label a new assignment. Technical details separate current assignment progress, the candidate attempt, the last verified generation and the reported workload state. A claimed successful attempt is insufficient without the existing activation evidence. Failed canary details explain that device retry does not restart the rollout or release waiting devices. Warning surfaces must remain readable in both themes.

Each device retry wait belongs to its displayed assignment and eligibility. A changed assignment, pause, revoked access, retry support or operating permission retires the old wait and feedback; returning to the same values cannot revive it. A new eligible review must not inherit an old busy latch. Benign heartbeat/name changes and changes between roles with the same operating authority do not interrupt the review. Stop waiting when leaving or ending the session, without implying server cancellation. Keep identity-recovery reviews independent. Agent-settings dialogs invalidated by lost authority or device access stay closed when access returns.

Deployment recovery reminders persist across tabs and browser restarts on the same origin, with separate actor/request records so tabs cannot overwrite one another. Persist the frozen reviewed request before sending; if local storage is unavailable, explain the issue before creation. A lost or malformed response opens recovery, never a fresh create button. Supported servers reuse the same identity and payload; older servers offer history without blind retry. Closing recovery leaves a quiet reminder, several outstanding requests use a compact choice list, and success links to the exact deployment without claiming device activation. Cross-tab completion updates the reminder; a failed browser cleanup does not hide a known successful result. Active hints expire after a crashed tab and are never treated as server truth.

Deployments and Schedules expose **Your recent requests** only when the server advertises actor-scoped discovery. This explicit, bounded view lists saved results across browsers without labeling acknowledged requests as pending. It offers exact result and original-rollback links, request type, saved time and current deployment status. No retry is reconstructed from history, and missing results do not imply failure. Reads have a deadline and cancel on dismissal or filter changes; Refresh is explicit. Active canary overlaps appear during review with a direct link and are checked again on creation. Device detail presents independent pipeline and agent-settings assignment provenance; absent assignments do not imply that a local Vector process exists.

Each workspace page has one restrained circle-help icon directly beside its title. The shared `PageHeader` accepts a topic and optional section; custom editor and panel titles use the same `HelpLink`. The icon has a descriptive accessible name and tooltip, a visible keyboard focus ring, and a minimum 28-pixel target. It opens the relevant guide in a new tab and retains only the current pipeline identity when applicable, leaving pending fields and unsaved drafts in place. Do not place detached “Page guide” links in toolbars or add a help icon to every term. Inline explanations such as VRL, input patterns, and secret references remain descriptive text links. Component documentation uses the same icon treatment and its official Vector reference URL.

The platform Help center is a separately built Astro Starlight site at `/help/`, served with the installation. It uses the same local Instrument Sans, warm surfaces and cobalt accents as the workspace. Task guides, troubleshooting, administration and reference topics have full-text local search and section navigation. Context links open the relevant section in a new tab, preserving even unfinished editor input. The site and its local search are available before sign-in. The authenticated API reference uses the bundled Scalar renderer with same-origin session requests; the device API is documented without pretending the browser has an enrolled device identity.

The [Cloudflare documentation reference](https://developers.cloudflare.com/workers/get-started/guide/) was inspected in the browser on 2026-09-26, including its rendered article, navigation, page actions and computed typography. Its useful patterns are stable navigation, a readable article column, compact Markdown actions and a clearly marked current section. Vectory keeps its own Instrument Sans, warm paper/charcoal palette and cobalt accent. Outline icons accompany navigation text; article breadcrumbs use the sidebar's actual grouping. Whole-page Markdown includes the complete guide and working links. Application references link to exact views, retaining only a valid pipeline context and asking the user to select a pipeline when none is known. Links never trigger save, publish, deploy or test actions.

Test real create/edit/publish/target, enrollment, recovery and account workflows. Review desktop, dark and narrow-screen layouts visually as well as with keyboard and accessibility checks. Ordinary views must never invent fleet data or telemetry. Screenshots and integration fixtures identify synthetic data explicitly. No runtime CDN, hosted font, analytics or external account is required.

The [official Vector reference map](VECTOR-REFERENCES.md) governs configuration semantics; the pinned executable and native tests establish compatibility. Automated schema coverage is evidence about field representation, not proof of every remote integration or an intuitive experience.

Device identity recovery uses a device-scoped request card and the same hide/reopen/acknowledge secret lifecycle as enrollment. Explain token authorization separately from host replacement. A lost response cannot expose a fresh create action until exact cancellation is confirmed. Status includes token use, and cancellation copy distinguishes an unstarted host from pending or completed replacement; it never suggests discarding recovery files.

Device access revocation uses one focused, closeable review dialog for Operators and Admins. Check the exact identity before confirmation, save a nonsecret actor/device reminder before sending, and require an identity-bound status or receipt before reporting revocation. An uncertain reply triggers only a bounded read; a current active result permits a separate deliberate confirmation with the pending-arrival warning. Closing or leaving cancels the client wait and suppresses late UI results without claiming server rollback. Keep confirmed access state visible even if reminder cleanup fails. Explain group and persistent-target removal separately from the host-owned Vector process and files.
