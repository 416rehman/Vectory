Required adversarial acceptance includes enrollment races/retries/token limits; all roles and CSRF; revoked pooled mTLS; recipient/nonce/signature/hash/generation attacks; local pause/drift; capability bypass; path/link permissions; real Vector failure/rollback and journal crash boundaries; targeting/conflicts/scheduler/canary gates; browser keyboard/accessibility; outage/queues/load; old-backup generation recovery. Read actual tests and their outputs before marking any item passed. An empty table cell is not a passing gate.

The 21 independent real-server subtests cover anonymous enumeration; one-time bootstrap and CSRF; viewer/editor/operator restrictions; untrusted CA, wrong hostname and TLS 1.2 rejection; spoofed proxy identity headers; malformed/out-of-scope/exhausted/revoked tokens; invalid CSR signature; server-selected certificate identity/EKU; original-key enrollment retry; duplicate-name race; signed nonce/recipient binding and payload tamper; cross-device artifact/status isolation; active revocation on a reused TLS connection; MFA TOTP/recovery-code replay and session revocation; and exact-name administrator recovery to a new unmanaged identity. This suite does not simulate an expired certificate, long outages, disk exhaustion, or service reboot.

Additional executed UI/native checks (lead integration):

- Rust backend: 24 tests pass, including native Vector worker execution, reviewed target membership, current-generation verification, removed-assignment terminal state and Windows SQLite restart handling. Final server SHA256 is recorded in the independent security gate above.
- Dashboard unit tests: six canonical graph cases, including opaque-field preservation, named route/OTLP/remap ports, type compatibility, cycles and duplicate inputs.
- Playwright: ten real-server browser tests pass against the production bundle served by the Rust API on port 8080. Coverage includes light/dark/mobile presentation; editor autosave/import/publish/history; publication during an in-flight autosave; actual native metrics and persisted history; token/group/policy workflows; MFA setup and one-use recovery login; exact-name device recovery authorization; reviewed scheduled target refresh and assignment removal; and a persisted 201-component canvas. Tests use isolated, explicitly synthetic fixtures. Repeated test runs use distinct assignment priorities so unrelated fixture policies correctly remain conflict protected.
- Resource loading: six focused lifecycle/race checks pass with the actual React hook in Chromium and explicitly synthetic delayed transport responses. Older requests cannot overwrite a newer response or a different resource; null paths and unmount invalidate pending work. See `resource-race.json`.
- Automated WCAG 2 A/AA and 2.1 AA checks report no violations on sign-in, overview, dark/mobile overview and editor. This is automated evidence, not a complete manual accessibility certification. Raw results are in `docs/evidence/accessibility*.json`.
- `node tests/catalog.mjs`: all 13 curated component fixtures pass real pinned Vector 0.58.0 syntax/topology validation. Endpoint connectivity/environment checks are excluded in catalog fixtures and retained by native agent validation.
- `node tests/contracts.mjs`: 112 actual persisted response bodies pass the shared JSON schemas, including secret template metadata and telemetry history. The count reflects the current isolated fixture population, not distinct API operations.
- `node tests/fleet-browser.mjs`: 1,000 synthetic offline inventory rows in a fresh SQLite database, served by the actual Rust API and built dashboard. Real 12-row pagination, name search and checked-device bulk preview pass; one observed render 234 ms, search 23 ms. The 201-component canvas rendered in 408 ms and opened its code view in 184 ms in the final browser run. These are single local UI observations, not native fleet capacity.
- `tests/native-outage.ps1`: the actual supervised Vector process and exact managed digest survive a 32-second control-plane outage at a 10-second heartbeat interval; agent reconnects in four seconds after restoration with its verified generation intact. This bounded test does not qualify multi-hour outages or physical power loss.
- The native full-stack secret/telemetry workflow verifies a signed template through actual Vector activation, receiver-observed HTTP credential use and same-generation rotation, unchanged template hash, changed effective hash and monotonic secret revision. Tested server response endpoints contain neither generated secret value. Five real component metric entries reach the persisted API; no pipeline events enter Vectory. See `native-secret-telemetry.json` for measured values and scope.
