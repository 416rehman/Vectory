# Vectory v1 contract

Status: implementation contract, 2026-09-26. JSON uses snake_case. UUIDs are server-generated strings; timestamps RFC3339 UTC; counters nonnegative integers. API errors: `{ "error": { "code": "CONFLICT", "message": "safe human message" } }`. Successful responses are direct objects/arrays, no envelope. Codes: UNAUTHENTICATED, FORBIDDEN, INVALID_INPUT, NOT_FOUND, CONFLICT, STALE_REVISION, ENROLLMENT_FAILED, RATE_LIMITED, VALIDATION_FAILED, CAPABILITY_DENIED, INTERNAL. Request bodies limited to 1 MiB, artifacts 1 MiB. SHA256 is lowercase hexadecimal over exact UTF-8 artifact bytes; layout does not enter the artifact.

## Dashboard API /api/v1

- GET /status -> `{initialized:boolean,version:string}` (public, no fleet data)
- POST /bootstrap `{bootstrap_secret,email,password,name}` -> `{user,csrf_token}` with session cookie. One-time locally provisioned secret.
- POST /login `{email,password}` -> `{user,csrf_token}`; POST /logout; GET /session -> `{user,csrf_token}`. Mutations require X-CSRF-Token; cookie HttpOnly SameSite=Strict Secure in production. User `{id,email,name,role}` role viewer/editor/operator/admin.
- GET /overview -> `{devices_total,devices_online,configurations_total,deployments_active,issues_open,devices:Device[],recent_activity:Audit[]}` (missing metrics null)
- GET /devices -> Device[]; GET /devices/{id} -> Device; POST /devices/{id}/revoke; GET /groups -> Group[]; POST /groups `{name,description,device_ids}` -> Group; PUT /groups/{id} same. Group `{id,name,description,device_ids}`.
- GET /configurations -> Configuration[]; POST /configurations `{name,description,graph,config}` -> Configuration; GET /configurations/{id} -> Configuration; PUT /configurations/{id}/draft `{revision,graph,config,message}` -> Configuration, 409 stale revision; GET /configurations/{id}/revisions -> Revision[]; POST /configurations/{id}/validate `{config}` -> `{valid,errors:string[],warnings:string[]}`; POST /configurations/{id}/publish `{revision,message}` -> Version; GET /configurations/{id}/versions -> Version[]; GET /versions/{id} -> Version.
- Configuration `{id,name,description,revision,graph,config,updated_at,created_at}`; graph `{nodes:[],edges:[]}` React Flow format. Config is semantic Vector JSON object preserving unknown fields. Revision `{id,configuration_id,revision,graph,config,message,created_at,author}`. Version `{id,configuration_id,number,graph,config,artifact,sha256,size,created_at,message,validation}`.
- GET /deployments -> Deployment[]; POST /deployments/preview `{version_id?,policy?,selector,priority,target_mode,rollout,scheduled_at?}` -> `{devices:Device[],conflicts:[],warnings:string[]}`; POST /deployments same -> Deployment; POST /deployments/{id}/cancel; POST /deployments/{id}/pause; POST /deployments/{id}/resume; POST /deployments/{id}/rollback -> Deployment. GET /deployments/{id} -> Deployment.
- Selector `{device_ids:string[],group_ids:string[],exclude_ids:string[]}`; union minus exclusions. priority integer. target_mode `snapshot` or `persistent` (scheduled always snapshot). rollout `{kind:"all"|"canary",canary_size:1,batch_size:10,observation_seconds:60,failure_threshold:0}`. Deployment `{id,name?,version_id?,policy?,selector,priority,target_mode,status,scheduled_at?,created_at,targets:DeploymentTarget[],rollout}`. Target `{device_id,state,generation,error?}`. status scheduled/active/paused/completed/cancelled/failed/missed. Equal priority different payload conflicts transactionally. Only released targets receive generations; snapshot immutable.
- GET /policies -> PolicyRecord[]; POST /policies `{name,policy}` -> PolicyRecord; PolicyRecord `{id,name,policy,created_at}`. AgentPolicy `{heartbeat_seconds:60,sync_paused:false,telemetry_enabled:true}` with local hard bounds heartbeat 10..3600.
- GET /tokens -> Token[]; POST /tokens `{name,expires_hours,max_uses?,name_prefix?}` -> `{token:string,record:Token}` (secret displayed once); POST /tokens/{id}/revoke. Token `{id,name,expires_at,uses,max_uses?,name_prefix?,revoked,created_at}`.
- GET /releases -> available local artifact metadata array only `{name,os,arch,version,sha256,size,url,signed:boolean}`.
- GET /issues -> Issue[] `{id,device_id,code,stage,message,count,first_seen,last_seen,resolved}`; GET /audit -> Audit[] `{id,actor,action,target,outcome,created_at}`; GET /users -> User[]; POST /users `{email,name,password,role}`; GET /settings -> `{version,vector_version,heartbeat_seconds,telemetry_retention_days,instance_name}`.

Device `{id,name,os,arch,agent_version,vector_version,last_seen?,status,labels:{},desired_generation,reported_generation,desired_version_id?,actual_sha256?,apply_state,sync_paused,pause_acknowledged,telemetry?:{sampled_at,events_per_second?:number,errors?:number},assignment?:{id,priority,reason},created_at}`. No telemetry value means unavailable, never zero. Every device starts unmanaged and unapproved; enrollment does not grant group membership. Explicit operator targeting grants desired state.

## Agent protocol /agent/v1 on dedicated TLS listener

POST /enroll (verified HTTPS, no client certificate): `{protocol_version:1,request_id,token,name,csr_pem,os,arch,agent_version,vector_version}`. CSR must prove private key possession. Reply `{device_id,certificate_pem,ca_pem,signing_public_key,certificate_expires_at}`. CA and signing trust arrive only through verified server TLS. Public key base64 raw Ed25519 (32 bytes). Same request_id/key retries idempotent; never recover using name alone. Token verifier only persisted. Certificates have server-selected UUID identity and clientAuth usage.

POST /heartbeat (mTLS): `{protocol_version:1,request_id,nonce,boot_id,agent_version,vector_version,reported_generation,policy_generation,actual_sha256,apply_state,local_paused,remote_pause_acknowledged,telemetry?,error?}`. Identity derived from registered client certificate fingerprint, checked against revocation each request. nonce random 32 bytes base64. Reply signed envelope `{payload:base64,signature:base64}`. Signature Ed25519 over exact decoded payload bytes; payload JSON `{protocol_version:1,device_id,nonce,issued_at,expires_at,generation,policy_generation,policy,desired?:{version_id,sha256,size,artifact_path,vector_version}}`. artifact_path must be relative `/agent/v1/artifacts/{sha256}`. Agent validates recipient/nonce/time/signature and rejects stale generations or changed same-generation identity, persisting highest accepted generations before apply. Manifest validity 5 minutes, clock tolerance 60 seconds. No redirects.

GET /artifacts/{sha256} (mTLS) -> exact artifact bytes, only current released digest authorized. POST /renew `{csr_pem}` (mTLS, same device) -> enrollment credential fields; revocation every request. Retain last good workload after credential failure. No insecure fallback or token heartbeat.

## Apply state

`unmanaged`, `desired`, `downloaded`, `validated`, `written`, `reload_requested`, `verified_applied`, `verification_unknown`, `failed`, `rolled_back`, `paused`. Only verified_applied advances canary success. A rollback references older content with a newer generation. Drift hashes the actual managed file each poll. Local emergency pause OR remote policy pause; pause is acknowledged after prohibited work stops. Bounded sanitized errors never contain configuration or credentials.

## Validation and support

Pin Vector 0.58.0 for initial catalog. Run real validation against available binary; absent isolated server validation must be explicitly recorded as unverified, never marked Vector-validated. Default deny exec, secret command providers, environment substitution, arbitrary file roots/network destinations locally. Do not use a shell to invoke Vector. Native verified mode may supervise an explicitly adopted child Vector process from fixed local paths, validate staged config, stop old process, launch new one with exact sole managed config, and require startup acknowledgment plus bounded process liveness. Do not infer exact activation from unrelated health endpoint.

Target Go toolchain 1.26.x; installed older toolchains are development evidence only until updated. Native target claims require actual tests. Server runs single instance SQLite WAL FULL sync/foreign_keys/busy_timeout; one serialized writer transaction for assignment changes and enrollment. DB IDs and relations enforce uniqueness. Scheduling, candidate assignments and released device generations are durable.

## Additive security and operations routes

Generated `openapi.json` (served to authenticated users at `/api/v1/openapi.json`) and `protocol.schema.json` are produced by `node contracts/generate.mjs`. `tests/contracts.mjs` checks real response bodies against the shared schemas; the dashboard also validates primary responses with Zod. Authorization, cryptographic verification and semantic constraints are additional mandatory checks, not replaced by JSON Schema.

- `GET /mfa`, password-gated `POST /mfa/setup {password}`, `POST /mfa/confirm {code}`, and `POST /mfa/disable {password,code?,recovery_code?}`. Setup returns the authenticator secret once; confirmation returns one-use recovery codes. Login accepts optional `totp_code` or `recovery_code`. Codes are replay checked; changes revoke other sessions.
- `POST /devices/{id}/recover` returns `{token,record}` for a one-hour, one-use exact-name recovery authorization. Only an administrator may issue it. Its use revokes the old identity, creates a new UUID, and transfers no groups/assignments. The agent's local `recover-enrollment` operation is explicit and journaled; network failures never trigger identity replacement.
- `POST /devices/{id}/retry` is rate limited and releases a new generation for a managed device. `POST /deployments/{id}/refresh-preview` and `/refresh {expected_device_ids}` review and transactionally refresh an unactivated schedule. `/unassign-preview` has no committed effect; `/unassign` removes the candidate and re-resolves devices. With no remaining assignment, retain the local working workload and become unmanaged. Unassigned deployment status is `unassigned`.
- Deployment creation accepts optional `expected_device_ids`. The dashboard always sends the exact reviewed preview IDs; the server rejects a changed selector resolution transactionally with HTTP 409. Removing an assignment is terminal for that deployment: cancel or rollback cannot resurrect it.
- `POST /vrl/test {program,sample}` executes only user-provided synthetic JSON through the configured isolated validator and returns `{valid,output,errors}`. Limits are 16 KiB program, 64 KiB sample, five seconds, 32 KiB output and two worker slots. Missing isolated execution returns capability unavailable, never host execution or invented results.
- `GET /devices/{id}/telemetry` returns `{device_id,samples}` with up to 120 chronological persisted minute buckets. No sample or missing metric means unavailable. Current samples and charts retain timestamps and show stale data distinctly.

## Local secrets and signing continuity

Exact `vectory-secret:NAME` references are permitted only in a bounded explicit set of sink credential fields. Names map to protected absolute files configured by the host operator. Resolution is literal JSON-string replacement, not a shell, environment interpolation, structural templating or remote secret distribution. The agent verifies pinned file handles, rejects unsafe links/permissions, applies the effective local capability policy, and runs actual Vector validation. Secret-bearing diagnostics omit subprocess output. Rendered working/recovery artifacts remain private; server history, exports and ordinary API responses retain references only.

Published versions mark `uses_local_secrets` after static reference validation. Heartbeats may include `applied_template_sha256` and monotonic `secret_revision`; `actual_sha256` always means actual effective managed bytes. Ordinary versions still require exact equality to the published artifact digest. For a secret-bearing version, verification additionally requires the current template digest and nonregressing secret evidence. A local file rotation triggers a tracked, journaled attempt and verified activation even at the same desired configuration generation. Failed/rolled-back attempts never become a new verified last-good artifact.

Signing-key rotation is a stopped-server maintenance operation. Each active credential is bound to the signing key it trusts; the server retains bounded old keys until authenticated renewal conveys new trust. Key pruning cannot remove a key referenced by an active credential. Restoring an old server backup must fence generations above explicitly collected per-device high-water marks; it never resets the agent's accepted counters. See the maintenance CLI and backup/restore guide for the review/apply procedure.
